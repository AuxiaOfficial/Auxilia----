# 验收清单

> 用法：每个阶段结束，开一个 QA 会话，把对应表格贴进去让它逐条判定。
> QA **只报告不修改**。不通过的必须带「期望 → 实际 → 复现步骤 → 严重级别」。

---

## 0. 最终的 6 条终验（v1 完成的唯一标准）

| # | 场景 | 必须做到 |
|---|---|---|
| ⬜ 1 | 装好后开机自启，`Shift+Space` 唤起 | 软件在托盘，快捷键全局有效，窗口 200ms 内出现并聚焦搜索框 |
| ⬜ 2 | 从零建一个 25 分钟倒计时任务 | 全程键盘 + ≤1 次鼠标点击，≤5 秒开跑 |
| ⬜ 3 | 跑的过程中关闭主窗口 | 托盘图标仍在，顶栏浮条时间持续减少，无卡顿 |
| ⬜ 4 | 归零 → 结束 → 三问 → 休息 | 链路不断，数据入库正确 |
| ⬜ 5 | 第二天打开 | 成就页有昨天热力图格子，任务显示等级和 coin |
| ⬜ 6 | 空闲放一整天 | 内存 ≤ 120MB，CPU ≈ 0% |

## 2. 回归测试清单（每完成一期都要重跑）

> AI 改 A 模块时打坏 B 模块是常态。以下 10 条是**每次改动后**必跑的冒烟测试，5 分钟能跑完。

| # | 冒烟项 | 为什么容易坏 |
|---|---|---|
| ⬜ 1 | `Shift+Space` 唤起 / 隐藏 | 窗口管理一改就可能失效 |
| ⬜ 2 | 新建一个任务 → 出现在列表 | 数据层改动最先影响这里 |
| ⬜ 3 | 拖一个任务进 TL → 重启后还在 | 拖拽 + 持久化双链路 |
| ⬜ 4 | 跑一个 1 分钟任务 → 归零 → 结束流程走完 | 计时 + 提示 + 结束三段链 |
| ⬜ 5 | 跑任务时关窗口 → 托盘时间在走 | 隐藏卸载逻辑 |
| ⬜ 6 | 左栏搜索中文能搜到 | 编码相关，易被改坏 |
| ⬜ 7 | 成就页打开不报错、不出现 NaN | 统计数据变更 |
| ⬜ 8 | 切换所有 view（home/focus/finish/achievements/review/wall/settings） | 视图状态机 |
| ⬜ 9 | 窗口缩到 950px 布局不乱 | 响应式 |
| ⬜ 10 | 空闲 5 分钟 CPU 回落 | 定时器泄漏 |

## 3. 严重级别定义

| 级别 | 判定 | 处理 |
|---|---|---|
| **阻断** | 核心流程走不通（不能计时、不能存数据、启动崩溃） | 必须修完才能进下一期 |
| **严重** | 功能可用但结果错（时长不准、数据丢失、落位偏移） | 本期修完 |
| **轻微** | 视觉/文案/边缘 case 不符 | 可累积到 P9 统一修 |

## 4. QA 会话的开场（复制即用）

```text
【角色】你是 Auxilia 项目的验收官。唯一职责是找问题，不是修问题。

【被测阶段】P{X}
【被测范围】{列出本期新增/修改的文件}
【依据】
1. prompts/P{X}-*.md 的「验收标准」章节
2. docs/01-产品规格书.md 第 6 章边界条件
3. 本文件第 2 章的回归清单

【要求】
1. 逐条判定：通过 / 不通过 / 无法验证（无法验证要说明缺什么条件）
2. 不通过项写：期望行为 → 实际行为 → 复现步骤 → 严重级别
3. 不要因为代码看起来对就判通过，说明你依据什么判定
4. 最后给出：阻断 N 项 / 严重 N 项 / 轻微 N 项，以及"是否可进入下一期"
5. 不要修改任何文件
```
