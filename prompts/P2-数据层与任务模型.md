## 任务

### 2.1 完整建表

把 `docs/02-技术架构.md` 第 5.1 节的 SQL 原样落到 `src-tauri/migrations/001_init.sql`。

要求：

- 用 `tauri-plugin-sql` 的 migrations 机制，确保**重复执行不报错**（用 `IF NOT EXISTS` 或依赖插件的版本记录）
- 打开 `PRAGMA journal_mode = WAL` 和 `PRAGMA foreign_keys = ON`
- 抽查：`sqlite3 auxilia.db ".tables"` 应列出 13 张表

### 2.2 Rust 模型层

`src-tauri/src/models.rs`：
```rust
#[derive(Serialize, Deserialize, Clone, Debug)]
#[serde(rename_all = "camelCase")]
pub struct Task { /* 与 tasks 表一一对应，字段用 camelCase 给前端 */ }
```
对应 `TaskRun` / `TaskLine` / `TaskLineEntry` / `Badge` / `Review` 都要有。

要求：
- 枚举用 `#[serde(rename_all = "lowercase")]` 的 Rust enum，**不要用 String 传状态**（前端拿不到类型提示，且拼错无报错）
- 时间字段统一 `i64` 毫秒
- 可空字段用 `Option<T>`

### 2.3 IPC 命令

`src-tauri/src/commands.rs`，本阶段实现：

| 命令 | 说明 |
|---|---|
| `task_create(payload)` | 插入，返回完整 Task |
| `task_update(id, patch)` | 部分更新，自动维护 `updated_at` |
| `task_delete(id)` | **软删除**：置 `deleted_at`，不物理删 |
| `task_hard_delete(id)` | 仅用于 disposable 任务完成时 |
| `task_list(query)` | 支持关键词搜索、状态过滤、排序 |
| `task_get(id)` | 单条，含历史 runs |
| `task_batch_delete(ids)` | 事务内批量软删 |

要求：
- 每个命令返回 `Result<T, String>`，错误信息要能看懂（不要返回 `database error 5`）
- 写操作全部包在事务里
- `task_list` 必须排除 `deleted_at IS NOT NULL`
- 搜索用 `title LIKE '%kw%' OR note LIKE '%kw%'`，不区分大小写

### 2.4 前端数据封装

### 2.5 状态管理

`src/store/taskStore.ts`（Zustand）：
```ts
interface TaskStore {
  tasks: Task[];
  keyword: string;
  loading: boolean;
  error: string | null;
  fetch(): Promise<void>;
  setKeyword(kw: string): Promise<void>;
  create(input: NewTaskInput): Promise<Task>;
  update(id: string, patch: Partial<Task>): Promise<void>;

```
要求：
- 所有写操作成功后**局部更新本地数组**，不要每次全量 refetch（省 IPC）
- 搜索做 250ms 防抖
- `loading` / `error` 状态必须被 UI 消费（本期可以先只 console，但状态本身要有）

### 2.6 任务池 UI（最小可用）

把左栏从占位变成真列表：
- 顶部搜索框（无边框，只有一条底部 1px 极淡下划线，聚焦时变亮）

## 关键要求

1. **软删除是硬要求。** disposable 任务完成后走 `task_hard_delete`，其余一律软删。历史统计要能关联到已删任务。
2. 前端**不许**自己拼 SQL。`lib/db.ts` 之外出现 `execute(` 或 `invoke('task_` 即为违规。
3. 时间戳一律毫秒。插入时 `Date.now()`，不要用秒。
4. `level` 在 Rust 侧写入时同步计算：`level = floor(total_seconds / 6000) + 1`。
5. 一切字符串进库前做 trim，标题为空直接拒绝。

## 验收标准

| # | 检查项 | 判定 |
|---|---|---|
| 1 | `auxilia.db` 中 13 张表全部存在 | `.tables` |
| 2 | 关闭软件再打开，之前建的任务还在 | 重启验证 |
| 3 | 新建任务 → 列表出现 → 重启仍在 | 手动 |
| 4 | 改标题 → 重启后是新的 | 手动 |
| 5 | 删除任务 → 列表消失 → **数据库里记录还在，只是 `deleted_at` 有值** | 查库验证 |
| 6 | 搜索"abc"能匹配标题和备注，中文也能搜 | 手动 |
| 7 | 批量删 3 条，事务原子，要么全删要么全不删 | 断点验证或看日志 |
| 8 | 标题为空时保存被拒绝且有提示 | 手动 |
| 9 | 标题前后空格被 trim | 查库 |
| 10 | 新建 disposable 任务并完成 → 数据库无此行 | 查库 |
| 11 | 前端代码里没有 `invoke('task_` 直接调用（除 db.ts） | 全局搜 |
| 12 | TypeScript 无 `any`，`pnpm tsc --noEmit` 通过 | 命令 |
