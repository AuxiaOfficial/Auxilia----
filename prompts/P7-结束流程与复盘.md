# P7 · 结束流程与复盘系统

**角色**：前端工程师（R3）+ 视觉设计师（R2）
**前置**：P6 通过验收
**验收官**：R5

---

## 目标

任务结束后，把用户"按在椅子上"面对一次真实的反思。以及让复盘从"应该做但不会做"变成"红点一出现就想点"。

**这一期决定产品是不是只是个计时器。**

---

## 第一部分 · 结束流程（FR-F1 ~ FR-F5）

### 7.1 三段式，不可跳过

```
① 完成确认  →  ② 三问反思  →  ③ 休息提示
```

三段在同一个全屏视图里**顺序推进**，不是三个页面。用 `AnimatePresence` 做前进/后退的横向位移（`x: 24 → 0 → -24`，`--dur-slow`）。

### 7.2 第一段：完成确认

```
                    ✓                      ← 24px，--text-2，淡入时描边动画

                 写方案                     ← 18px，--text-2

                1 小时 12 分                 ← 56px，300 字重，--text-1
              比计划多用了 12 分钟            ← 11px，--text-3（正计时任务不显示此行）

              + 144 coin                    ← 13px，--warn 的 60% 透明度

                  [ 记录一下 ]                ← 文字按钮
```

- 时长数字有一个从 0 滚动到目标值的动效（400ms，`--ease-out`），像计数器
- 如果升级了 `level`：coin 下方多一行 `等级提升 Lv.2 → Lv.3`，配一次极轻的发光（用 `box-shadow: 0 0 24px rgba(255,184,77,0.15)`，注意 P0 说禁止彩色阴影——这是唯一例外，且不超过 24px）
- 「记录一下」点进去 → 第二段
- **允许直接 Esc 退出**（不强迫，但退出后该 run 标记为 `reflection_skipped`）

### 7.3 第二段：三问（逐问递进）

**不要一次性放三个输入框。** 一次只问一个问题，上一问的回答以对话气泡形式在上方淡出保留。

```
  这次的结果，和你一开始的预期，
  差在哪里？                              ← 22px，--text-1，行高 1.5

  ┌──────────────────────────────────┐
  │ 比想象中难，卡在数据对齐上，       │   ← 无边框 textarea，15px，
  │ 实际只写完了大纲                   │      placeholder: 想到什么写什么
  └──────────────────────────────────┘

                       [ 下一问 ]        ← 有内容才亮，空时可点但淡
```

三问文案（**逐字使用，不要改写**）：

| # | 问题 | 对应字段 |
|---|---|---|
| ① | 这次的结果，和你一开始的预期，差在哪里？ | `outcome` |
| ② | 从哪个瞬间开始，这件事本可以做得更好？ | `reflect_moment` |
| ③ | 下次你会具体改做什么？ | `reflect_next` |

交互：
- 第 ① 问上方显示用户一开始写的 prospect（如果有）：`你的预期：把方案写完`（11px `--text-3`，左侧一根 2px 竖线）
- 这样才有"预期 vs 实际"的对照感，这是 P3 哲学的核心呈现
- 每题 textarea 自动增高，最大 200px
- 回车换行，`Ctrl/Cmd + Enter` 进入下一问
- 第三问后按钮变成「完成」
- 每题都可以留空（不强迫），但空着点"下一问"时按钮文字变「跳过这问」，让用户明确知道自己在跳过

### 7.4 第三段：休息提示

```
                站 起 来                 ← 24px，字间距 0.1em

           已经坐了 1 小时 12 分钟
              去倒杯水，走两步

        [ 休息 5 分钟 ]    [ 结束 ]        ← 主按钮反色，次按钮文字
```

- 「休息 5 分钟」→ 创建一个临时 countdown 任务（标题「休息」，5 分钟，`disposable`，`display_mode='topbar'`），立即开始
- 「结束」→ 回 home
- 这一段停留 3 秒后才显示按钮（给一点静默，不要急着让人点走），期间只有文字淡入

### 7.5 中止流程（FR-F5）

中止不进入三问。只弹一个极简确认：

```
这次「写方案」要放弃吗？
已专注 34 分钟，不会计入成就。

         [ 确认放弃 ]   [ 继续做 ]
```
确认后直接回 home，左栏该任务有一次轻微抖动（`x: 0 → -3 → 0`，160ms）作为反馈。

## 第二部分 · 复盘系统（FR-H1 ~ FR-H6）

### 7.6 红点逻辑

`uiStore` 里派生 `hasPendingReview: boolean`：

```ts
// 三个独立周期的判定，任一为真即显示红点
daily:   now >= 今日 daily_hour 点 && reviews 中不存在 period='daily' 且 period_start=今天
weekly:  now >= 本周 weekly_dow 的 weekly_hour && 不存在本周的 weekly 复盘
monthly: now >= 本月 monthly_dom 的 monthly_hour && 不存在本月的 monthly 复盘
```

- 满足条件的周期数 > 1 时，入口右侧红点变成一个小的数字（`2`）
- 红点 8px，`--danger`，无脉冲动画（要克制，不要做成提醒炸弹）
- 每分钟重算一次（用一个 `setInterval(60000)`，窗口隐藏时停）

### 7.7 设置面板

「任务复盘」页右上角一个齿轮，展开设置（行内展开，不弹窗）：

```
每日复盘    [开关]  在 21:00 提醒
每周复盘    [开关]  周日 20:00
每月复盘    [开关]  1 日 10:00
归档目录    ~/Documents/Auxilia/reviews   [更改]
```
- 时间用与 P4 同一个滚轮组件的简化版（只有小时轮），**复用，不要重写**
- 目录选择用 `tauri-plugin-dialog` 的 `open({ directory: true })`

### 7.8 复盘向导

点击「任务复盘」→ 进入 `view = 'review'`。

**第一步：数据摘要（自动生成，只读）**

先给用户看"这周到底发生了什么"，再问他问题。顺序反了用户会空写。

```
2026 年第 43 周 · 10.20 - 10.26

12 小时 30 分          18               7
总专注                 完成任务          中断次数

写方案            3h 20m    ████████████
回邮件            1h 50m    ██████
读书              1h 05m    ████
```
- 数据由 SQL 聚合得出（不要拉全表到前端算）
- 三行细条形图，纯 SVG，长度按占比

**第二步：提问模板**

按周期类型给不同的问题集，全部是 textarea，**预填 Markdown 结构**（用户直接在里面写，所见即所得的极简富文本——实际上就是等宽字体的 textarea）：

周复盘模板：
```markdown
## 这周做得最好的一件事是什么？


## 哪段时间被浪费了？为什么？


## 下周我要停止做的一件事


## 下周我要开始做的一件事
```

日复盘模板（更短）：
```markdown
## 今天最重要的一件事完成了吗？


## 明天第一件事做什么？


```

月复盘模板：
```markdown
## 这个月最大的变化是什么？


## 哪件事做得最多但价值最低？


## 下个月要砍掉什么？


```

**第三步：归档**

点「归档」→
1. 拼装完整 Markdown（头部含周期、数据摘要）
2. 写入 `export_dir/{YYYY}/{YYYY-MM-DD}-daily.md` 或 `{YYYY}-W{WW}-weekly.md`
3. 写入 `reviews` 表（含 `file_path`）
4. 顶部短暂显示「已归档到 2026/2026-10-25-daily.md」，带一个「打开文件夹」链接
5. 红点消失

文件头部格式：
```markdown
---
period: weekly
range: 2026-10-20 ~ 2026-10-26
total_seconds: 45000
tasks_done: 18
interruptions: 7
---

# 2026 年第 43 周复盘

> 总专注 12 小时 30 分 · 完成 18 个任务 · 中断 7 次
> 耗时最多：写方案（3h 20m）

（用户填写内容）
```

### 7.9 历史复盘

复盘页下方一个可展开列表，按时间倒序：
```
2026-W43  周复盘  12h30m   ›
2026-W42  周复盘  10h05m   ›
2026-10-24 日复盘  —       ›
```
点击 → 展示只读的 Markdown 渲染（不要引 markdown 库，用极简的正则处理标题/粗体/列表即可，或者直接显示等宽原文）。

## 关键要求

1. **三问必须逐问出现**，一次一个。三个输入框并排会让人一个字都不想写。
2. prospect 与 outcome 的对照必须可见。没有预期就没有"差量"，P3 哲学就落空了。
3. 统计聚合全部走 SQL（`GROUP BY date(started_at/1000,'unixepoch','localtime')`），禁止 `SELECT *` 后在前端遍历。
4. 复盘文件写入失败时**必须明确报错**（路径不存在/无权限），不能静默。同时保留 `content_md` 在库里，允许重试导出。
5. 时间滚轮组件复用 P4 的 `WheelPicker`，不要复制一份新的。

## 验收标准

### A. 结束流程

| # | 检查项 |
|---|---|
| 1 | 任务完成后进入完成确认，时长数字有滚动动画且最终值准确 |
| 2 | coin 收益 = `floor(active_seconds / 60) * 2`（正计时同）；中止 = 0 |
| 3 | 升级时显示 `Lv.x → Lv.y` |
| 4 | 三问逐条出现，上一问以淡化形式保留在上方 |
| 5 | 第一问上方显示原始 prospect（若为空则不显示该行） |
| 6 | 三问答案正确写入 `task_runs` 三个字段 |
| 7 | 每题留空可以跳过，跳过时按钮文案变为「跳过这问」 |
| 8 | 第三段出现「休息 5 分钟」，点击后创建并立即开始一个 5 分钟任务 |
| 9 | 中止流程不进入三问，只记 `result='aborted'`，coin 为 0 |
| 10 | Esc 中途退出不崩溃，run 正常闭合 |

### B. 复盘

| # | 检查项 |
|---|---|
| 11 | 到达设定时间后「任务复盘」入口出现红点 |
| 12 | 归档后红点消失，次日/次周重新出现 |
| 13 | 复盘页顶部数据准确（对照数据库 GROUP BY 手算） |
| 14 | 归档生成的 md 文件内容与模板一致，含 frontmatter |
| 15 | 归档目录不存在时自动创建；无权限时明确报错 |
| 16 | 历史复盘列表按时间倒序，点击可查看内容 |
| 17 | 修改复盘时间为 1 分钟后，到点红点正确出现 |
| 18 | 同时有日/周待复盘时红点显示数字 2 |

## 禁止

- ❌ 三个输入框并排
- ❌ 用 toast 提示归档成功（用行内文字）
- ❌ 强迫用户填完三问才能退出
- ❌ 在前端遍历全部记录做统计
- ❌ 引入 markdown 渲染库（历史复盘用极简处理或等宽原文）
- ❌ 给红点加脉冲/呼吸动画
