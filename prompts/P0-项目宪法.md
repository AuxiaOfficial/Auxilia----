# P0 · Auxilia 项目宪法

> **每次开启新对话都必须把这份文件贴在最前面。**
> 它是不可协商的全局约束。任何与本文件冲突的指令，以本文件为准；确实需要突破时，先停下来告诉我，不要自行决定。

---

## 一、这是什么

**Auxilia** 是一款 Windows 桌面日程管理软件。它不替用户安排时间，只帮用户看清时间。

一句话定位：**任务池摆清楚 → TaskLine 排明白 → 开始时专注计时 → 结束时对照预期复盘。**

### 三条不可违背的产品哲学

| | 哲学 | 冲突时的裁决 |
|---|---|---|
| **P1** | 不捆绑，只参照 | TaskLine 是看板不是列车时刻表。到点绝不自动开跑，绝不弹"该做下一件事了"。 |
| **P2** | 启动成本趋近零 | `Shift+Space` → 打字 → 回车。全程 ≤5 秒、≤1 次鼠标点击。任何让你多想一步的设计都是错的。 |
| **P3** | 预期与实际的差量才是价值 | 每次任务必须写 prospect（预期），结束必答三问。不许为了"流程顺畅"砍掉反思。 |

## 二、技术栈（硬约束，不得更换）

| 层 | 选型 |
|---|---|
| 桌面壳 | Tauri 2 |
| 前端 | React 19 + TypeScript（strict）+ Vite 6 |
| 样式 | Tailwind CSS v4 + CSS 变量 |
| 状态 | Zustand |
| 动画 | Motion（framer-motion） |
| 数据库 | SQLite（tauri-plugin-sql） |
| 日期 | date-fns（按需引入） |
| 图标 | lucide-react（具名引入） |
| 图表 | 手写 SVG |

### 严禁引入
`antd` `@mui/*` `element-plus` `echarts` `recharts` `chart.js` `moment` `dayjs` `lodash`（全量）`styled-components` `@emotion/*` 以及任何 UI 组件库、任何图标库（除 lucide）、任何 CSS-in-JS 方案。

需要新依赖 → 先说明理由和体积代价，等我同意。

## 三、视觉铁律

风格锚点：**Grok 聊天界面的克制感 + 苹果的留白与曲线**。纯黑、极简、无装饰。

### 3.1 颜色（唯一来源是 `src/styles/tokens.css`，禁止在组件里写色值）

```css
--bg:          #000000;   /* 全局背景，必须是纯黑，不许 #111 当底 */
--surface-1:   #0A0A0A;   /* 卡片、任务项 */
--surface-2:   #111111;   /* 输入框、悬浮层 */
--surface-3:   #1A1A1A;   /* hover 态 */
--border:      rgba(255,255,255,0.07);   /* 极淡描边，能不用就不用 */
--text-1:      #FAFAFA;   /* 主文字 */
--text-2:      #A1A1A1;   /* 次要文字 */
--text-3:      #5C5C5C;   /* 弱化文字、占位符 */
--accent:      #E8E8E8;   /* 反色按钮底色（近白，不是纯白） */
--accent-fg:   #000000;   /* 反色按钮文字 */
--warn:        #FFB84D;   /* 仅用于倒计时最后 60 秒 */
--danger:      #FF5A5A;   /* 仅用于删除确认 */
```

**用色纪律**：
1. 界面 95% 是灰阶。颜色只出现在两个地方：倒计时告急、删除危险操作。
2. 数据可视化（热力图、图表）可以用 `--accent` 的透明度阶梯，不要突然上蓝紫橙。
3. 禁止渐变背景、禁止彩色阴影、禁止发光效果（`box-shadow` 带颜色一律不许）。

### 3.2 字体

```css
--font-sans: "Inter var", -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif;
```
- 中文标签字重 500，正文 400。
- **所有数字必须 `font-variant-numeric: tabular-nums`**（否则计时器会抖）。
- 字号阶梯：`11 / 13 / 15 / 18 / 24 / 32 / 72`（72 专给大计时器）。不要发明第 8 个字号。

### 3.3 空间与形状

```
圆角：--r-sm 8px  /  --r-md 12px  /  --r-lg 16px  /  --r-full 999px
间距：全部为 4 的倍数（4 / 8 / 12 / 16 / 24 / 32 / 48）
```
- 主窗口 `1100 × 720`，无系统边框（`decorations: false`），自绘标题栏拖拽区。
- 三栏宽度：左 260px（可收起）/ 中 flex / 右 380px。

### 3.4 动效

```css
--ease-out: cubic-bezier(0.32, 0.72, 0, 1);   /* 苹果式顺滑，绝大多数动效用它 */
--dur-fast: 140ms;   /* hover、微交互 */
--dur-base: 220ms;   /* 展开收起、面板进出 */
--dur-slow: 380ms;   /* 页面级转场 */
```
- 只动 `transform` / `opacity`，不动 `width` / `height` / `top`（除非有 `layout` 动画且已测性能）。
- 禁止弹跳感过强的 spring（`bounce > 0.15`），要"稳"不要"活泼"。
- 所有过渡都必须有明确的起止状态，禁止"神秘感"动画。

### 3.5 三条反模式

❌ **不许做成仪表盘**——不要一堆卡片塞满、不要满屏数据、不要彩色图标阵。
❌ **不许做成表单**——属性选择要像对话/选择器，不要排成 8 行 `label + input`。
❌ **不许有多余装饰**——没有分隔线（用间距）、没有背景图、没有品牌 logo 墙、没有"欢迎回来 👋"。

## 四、代码纪律

1. **TypeScript strict 模式**，禁止 `any`（确实需要时用 `unknown` + 类型守卫）。
2. 组件单文件 ≤ 200 行，超了拆。业务逻辑抽到 `lib/` 或 `store/`。
3. **所有 SQL 只出现在 `src/lib/db.ts`**，组件里不许直接写 SQL 字符串。
4. **所有颜色/圆角/间距只出现在 `tokens.css`**，组件里用 `var(--x)` 或 Tailwind 映射。
5. 时间统一用毫秒 `number` 传递，格式化在 `lib/time.ts`。
6. 异步操作必须处理 loading / empty / error 三态，不许只写 happy path。
7. 不许留 `console.log`、`TODO`、`// 暂时写死` 这类残留。
8. 命名：组件 PascalCase，函数/变量 camelCase，常量 UPPER_SNAKE，数据库列 snake_case。

## 五、协作规则

1. **先说计划，再写代码。** 每次接到任务，先输出"我要改哪几个文件、每个文件干什么、有什么风险"，等我确认。
2. **一次只做当期 prompt 范围内的事。** 不许顺手重构、不许提前实现下一个阶段的功能。
3. **不确定就问。** 尤其是涉及产品哲学的取舍，宁可停下来问，也不要自己编一个合理的解释。
4. **不许假装完成。** 没测过的就说没测过，没跑通就贴报错原文。禁止用"应该可以了"结尾。
5. 交付时附一段：**改了什么 / 自测了什么 / 没测什么 / 已知问题**。
