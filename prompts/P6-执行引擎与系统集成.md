# P6 · 执行引擎与系统集成

**角色**：桌面工程师（R4）+ 前端工程师（R3）
**前置**：P5 通过验收
**验收官**：R5

## 目标

任务能真正跑起来：计时准确、窗口能藏、托盘能控、关机重启不丢数据。

**这一期是全项目最容易埋雷的地方。核心只有一句话：时间只用时间戳差算，永远不要累加。**

## 任务

### 6.1 新增迁移 `002_add_fired.sql`

scheduled 任务需要记录"是否已触发"，避免重启后重复提醒：

```sql
ALTER TABLE tasks ADD COLUMN last_fired_at INTEGER;
CREATE INDEX idx_tasks_sched ON tasks(duration_mode, scheduled_at) WHERE duration_mode = 'scheduled';
```

### 6.2 Rust 计时引擎 `engine.rs`

按 `docs/02-技术架构.md` 6.1 实现。核心结构：

```rust
pub struct RunState {
    pub run_id: String,
    pub task_id: String,
    pub mode: DurationMode,
    pub planned_seconds: i64,
    pub segment_started_at: Option<i64>,   // None = 暂停中
    pub closed_seconds: i64,
    pub paused_seconds: i64,
    pub interruptions: u32,
}
```

命令清单：

| 命令 | 行为 |
|---|---|
| `run_start(task_id, prospect)` | 若已有 running → 返回 `Err("BUSY")`。写 `task_runs`，开 segment，`tasks.status='running'`，写 `app_state.run_id` |
| `run_pause()` | `closed_seconds += (now - seg)/1000`，闭合当前 segment，`segment_started_at=None`，`tasks.status='paused'` |
| `run_resume()` | `segment_started_at=Some(now)`，插入新 segment，`interruptions += 1`，`status='running'` |
| `run_finish(feedback)` | 闭合 segment，写 `result='completed'`、三问文本，更新 `tasks.total_seconds` / `level` / `run_count` / `last_active_at`，清 `app_state.run_id`，结算 coin |
| `run_abort()` | 同上但 `result='aborted'`、`coin_earned=0` |
| `run_state()` | 返回当前 RunState（前端启动时同步用） |

**必须遵守**：
1. `active_seconds = closed_seconds + (segment_started_at ? (now - s)/1000 : 0)`，**任何地方都不许写 `elapsed += 1`**。
2. 每个写操作必须落库，且**先写库再改内存态**（崩溃时库是真相）。
3. `tasks.total_seconds` 只在 `run_finish` / `run_abort` 时累加，不做实时累加。

### 6.3 后台调度 `tokio::interval(500ms)`

只做四件事：

```rust
async fn tick(app: AppHandle) {
    let now = now_ms();

    // ① 倒计时归零
    if let Some(run) = engine.active() {
        if run.mode == Countdown && run.active_seconds(now) >= run.planned_seconds {
            emit(&app, "timer:finished", run.summary());
            // 注意：不要在这里自动 finish，交给前端走结束流程后调 run_finish
            // 但要标记 fired，避免每 500ms 重复 emit
        }
    }

    // ② scheduled 触发
    for task in due_scheduled(&now) {
        if engine.active().is_some() {
            emit(&app, "scheduled:conflict", task);   // FR-E7
        } else {
            start_auto(&app, task.id);                 // 直接开跑（FR-E7 的"打断"分支）
        }
        mark_fired(&app, &task.id, now);
    }

    // ③ 心跳（每 60s）
    if heartbeat_due(now) { write_heartbeat(&app, now); }

    // ④ 托盘 tooltip + mini 窗口文本（每 60s，别每秒调系统 API）
    if tooltip_due(now) { update_tray_and_mini(&app); }
}
```

**倒计时归零后必须置位 `fired` 标记**，否则每 500ms 都会 emit 一次。

### 6.4 崩溃恢复（E-2）

启动时（`lib.rs` 的 `setup`）：

```rust
// 读 app_state
// 若 run_id 非空 且 对应 task_runs.ended_at 为 NULL
//   → 说明上次异常退出 → emit("recover:pending", run_snapshot)
// 清空 app_state.run_id，clean_exit 置 0
```
前端收到后弹一个对话框：

```
上次的「写方案」没有正常结束
已专注 1 小时 12 分（截至 昨天 21:40）
[ 补记为完成 ]  [ 放弃这次 ]
```
- 补记 → 用 `ended_at = 最后一条 segment 的开始时间 + 已闭合时长`，`result='completed'`
- 放弃 → `result='crashed'`，不计 coin

### 6.7 Focus 视图

中栏独占（左右栏淡出并微移）。元素从上到下：

```
        写方案                     ← 18px, --text-2
                                  ← 32px 间距
       24:31                      ← 72px, 300 字重, tabular-nums
                                  ← 8px
   倒计时 · 预计 25 分钟            ← 11px, --text-3

                                  ← 40px
   [暂停]      [完成]      [中止]        ← 三个文字按钮，无边框
```

规则：
- 倒计时：显示剩余 `25:00 → 00:00`。**不显示小时位**（除非时长 > 1h）
- 正计时：显示已过时间 `00:31 → 12:03:44`
- 最后 60 秒：数字颜色转 `--warn`，并有 1s 周期的 `scale 1 → 1.02 → 1` 呼吸
- 暂停中：数字 `opacity: 0.35`，上方出现 11px「已暂停」
- 「完成」和「中止」都要二次确认（行内确认，不用 modal）：「完成」→ `这次做得怎么样？` 进结束流程；「中止」→ `确定放弃？此次不计入成就`
- 前端计时：`useEffect` 里 `setInterval(500)` 只触发重算，值由 `Date.now() - segmentStartedAt` 得出。**窗口隐藏时自动停表，显示时重算**

### 6.8 四个窗口

| 窗口 | 尺寸 | 配置 | 内容 |
|---|---|---|---|
| `main` | 1100×720 | 已有 | — |
| `mini` | 96×26 | `transparent:true, decorations:false, always_on_top:true, skip_taskbar:true, focused:false, shadow:false` | `● 24:31 写方案`，胶囊形，黑 60% + `backdrop-filter: blur(20px)` |
| `float` | 220×64 | 同上 + `resizable:false` | 任务名 + 大号时间 + 暂停/完成两个图标按钮，可拖动 |
| `flash` | 全屏 | 同上 + `fullscreen:true` | `rgba(255,255,255,0.16)` 纯色，显示 130ms 后自行 hide |

定位：
- `mini`：主屏顶部居中，`y = 0`，`x = (screenW - 96) / 2`。若任务栏在顶部则 `y = 任务栏高`
- `float`：首次出现在主屏右上角，之后记住用户拖动位置（存 `settings`）
- 显示器切换 / DPI 变化：监听并重新定位

窗口显隐由任务的 `display_mode` 决定：
- `topbar` → 运行时显示 `mini`，结束后隐藏
- `float` → 运行时显示 `float`
- `none` → 都不显示

### 6.9 提示（FR-C6）

三个开关独立生效，可叠加：

**弹窗**：`tauri-plugin-notification` 发系统通知（标题=任务名，正文=剩余时间或"已完成"）。**不要用自绘弹窗**，因为软件可能不在前台。

**闪屏**：`show()` flash 窗口 130ms 后 `hide()`。必须 `set_ignore_cursor_events(true)`，否则会挡住用户点击。

**铃声**：用 Web Audio 现场合成，**不要放音频文件**：
```ts
const ctx = new AudioContext();
const osc = ctx.createOscillator();
const gain = ctx.createGain();
osc.type = 'sine';
osc.frequency.setValueAtTime(880, ctx.currentTime);
gain.gain.setValueAtTime(0, ctx.currentTime);
gain.gain.linearRampToValueAtTime(0.18, ctx.currentTime + 0.01);
gain.gain.exponentialRampToValueAtTime(0.001, ctx.currentTime + 0.9);
osc.connect(gain).connect(ctx.destination);
osc.start(); osc.stop(ctx.currentTime + 0.9);
```
重复两次，间隔 0.25s，听感像"叮—叮"。柔和，不要尖锐。

⚠️ `AudioContext` 需要用户交互后才能播放。在每次 `run_start` 时 `ctx.resume()` 一次即可解锁。

## 关键要求

1. **单任务串行铁律**：`run_start` 时若已有 active run，直接 `Err("BUSY")` 并返回当前任务名，前端提示「正在执行「X」，先结束它」。不弹打断询问（打断询问只给 scheduled 用）。
2. 计时**绝对不许**用累加。代码审查时全局搜 `+= 1` / `elapsed++`，搜到就是错。
3. 所有窗口预创建，`hide()` 切换。`mini`/`float` 在无任务时也保持存在（隐藏），不要销毁。
4. 前端不得订阅任何"每秒推送"。只订阅 `timer:finished` / `scheduled:conflict` / `recover:pending` / `hotkey:failed`。
5. 任务结束后 `mini`/`float` 必须在 200ms 内消失。
6. `flash` 窗口每次显示前重置为透明，避免残留上一次的残影。

## 验收标准

### A. 计时准确性（最关键）

| # | 场景 | 期望 |
|---|---|---|
| 1 | 25 分钟倒计时跑完 | 误差 < 2 秒 |
| 2 | 跑 3 分钟后暂停 5 分钟再继续 | 结束后 `active_seconds` 不含暂停的 5 分钟 |
| 3 | 跑 5 分钟后让电脑休眠 30 分钟再唤醒 | 倒计时已归零 → 立即触发结束流程，`active_seconds` 含休眠时间（时间真实流逝） |
| 4 | 跑 5 分钟后用任务管理器杀掉进程 → 重启 | 弹出补记对话框，时长正确 |
| 5 | 计时中隐藏主窗口（Shift+Space）10 分钟 | mini 显示的时间持续减少，无跳变或卡住 |
| 6 | 计时中修改系统时间 | 不再追究（时间戳差本身就受影响），但不得崩溃 |

> 第 3 条要明确产品语义：**休眠期间时间照算**（因为那是真实的物理时间流逝）。如果你希望休眠暂停计时，需要额外记录 suspend/resume 事件——v1 不做，按"照算"实现。

## 禁止

- ❌ 任何形式的时长累加
- ❌ 每秒 IPC 推送
- ❌ 用自绘弹窗做系统级提醒
- ❌ 引入音频文件
- ❌ 销毁重建窗口
- ❌ 允许多任务并行
- ❌ 在 Rust 侧做 UI 决策（它只负责状态和系统能力）
