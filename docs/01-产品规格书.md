# Auxilia 产品规格书 v1.0

> 本文档是把原始需求翻译成**可验收规格**的结果。所有编号（FR-xx）在后续提示词和验收清单中被引用，请勿随意改动编号。
> 文中标注 ⚠️ 的地方是原始需求里的**歧义或技术现实问题**，已经在第 5 章给出决策，需要你确认或推翻。

---

## 1. 一句话定义

**Auxilia 是一个不捆绑你时间的桌面日程管理器。它帮你把要做的事摆清楚（任务池）、把一天排明白（TaskLine）、在你真正开始时专注计时，并在结束时逼你对照预期做一次复盘。**

## 2. 设计哲学（判断一切取舍的最高标准）

| # | 哲学 | 落地含义 |
|---|---|---|
| P1 | **不捆绑，只参照** | TaskLine 是看板不是列车时刻表。到点不自动开跑，绝不弹"该做下一件事了"。 |
| P2 | **启动成本趋近于零** | 全局快捷键 `Shift+Space` 唤起 → 打字 → 回车开跑，全程不超过 5 秒、不超过 1 次鼠标点击。 |
| P3 | **预期与实际的差量才是价值** | 每次任务必须写 prospect（预期），结束时必须面对 outcome（实际）。数据只是副产品。 |

> 任何实现方案如果与 P1/P2/P3 冲突，一律回到这三条重新决策。

---

## 3. 信息架构

三个空间，用左侧栏切换：

```
┌─────────────┬──────────────────────────────────┬─────────────────┐
│  任务池      │        中栏（主舞台）              │   TaskLine      │
│  (左侧)      │                                  │   (右侧)        │
│             │   常态：Slogan + 4 个入口           │                 │
│  · 搜索      │   专注时：大号计时器                 │   · 时间轴       │
│  · 任务列表   │                                  │   · 拖放落位     │
│  · 拖拽源    │                                  │   · 多 TL 切换   │
└─────────────┴──────────────────────────────────┴─────────────────┘
```

中栏 4 个入口：
1. **新建任务**
2. **新建 TaskLine**
3. **我的成就**
4. **任务复盘**

## 4. 功能规格

### A. 首次启动与引导

| 编号 | 规格 | 备注 |
|---|---|---|
| FR-A1 | 首次启动强制进入引导流，引导用户完整走一遍"新建任务 → 写预期 → 开始 → 结束" | 用一条示例任务走完，不写空教程页 |
| FR-A2 | 引导流程中要求设置唤起快捷键，默认 `Shift+Space`，冲突时提示并允许改 | 用系统级全局热键，软件在后台也能唤起 |
| FR-A3 | 引导完成后写入 `onboarded = true`，此后不再出现 | 允许在设置里手动重跑 |
| FR-A4 | 首次启动即注册开机自启（默认开启），设置项可见可关 | 见 FR-J1 |

### B. 任务模型

| 编号 | 规格 |
|---|---|
| FR-B1 | 任务必备字段：标题、持续性、持续时间模式、提示力度、显示方式 |
| FR-B2 | **持续性**三选一：`permanent` 总是存在 / `disposable` 完成即删除 / `expiring` 指定日期后自动删除 |
| FR-B3 | `expiring` 必须填到期时间，到期后任务进入"过期"态并在任务池中以低对比度显示 24h，之后硬删除 |
| FR-B4 | **持续时间模式**三选一：`countdown` 倒计时（有终点）/ `countup` 正计时（无终点）/ `scheduled` 固定时间点触发 |
| FR-B5 | 任务有等级 `level`，由该任务**累计专注时长**决定（见 FR-G4），等级只升不降 |
| FR-B6 | 任务可关联多个 TaskLine 条目（一个任务可出现在多个 TL 里） |

### C. 新建任务

| 编号 | 规格 |
|---|---|
| FR-C1 | 新建面板为**居中浮层**，背景压暗，不使用独立页面跳转 |
| FR-C2 | 五组属性按 持续性 → 持续时间 → 时长调整 → 提示力度 → 显示方式 的顺序单列展开，不堆成表单 |
| FR-C3 | `countdown` / `countup` 使用**双轮阻尼滚轮**（小时轮 + 分钟轮），每格 1 分钟，支持惯性、阻尼、吸附 |
| FR-C4 | 滚轮旁必须提供快捷胶囊按钮：25 分钟 / 45 分钟 / 1 小时 / 1.5 小时 / 2 小时，点击后滚轮**动画滚到**该位置（不是瞬移） |
| FR-C5 | `scheduled` 模式改用日期时间选择器，不用滚轮 |
| FR-C6 | **提示力度**三项独立开关：弹窗 / 屏幕闪一下 / 铃声 |
| FR-C7 | **显示方式**三选一：`topbar` 顶栏常显 / `none` 不显示 / `float` 浮窗 |
| FR-C8 | 保存成功后显示成功态，给两个动作：**马上开始** / **暂不开始**，不做第三个选项 |
| FR-C9 | 标题为空时不允许保存；标题输入框自动聚焦 |

### D. TaskLine

| 编号 | 规格 |
|---|---|
| FR-D1 | TaskLine 是**按小时分格的纵向时间轴看板**，不是执行队列 |
| FR-D2 | 支持创建多个 TL（如「周末 TL」「周一 TL」），左侧或顶部下拉切换 |
| FR-D3 | 把任务加入 TL 的方式：从左栏**拖拽**到某一时间格，或点任务后选「加入 TL」 |
| FR-D4 | 同一时间格可容纳多个任务，纵向堆叠显示，溢出不截断 |
| FR-D5 | **点击 TL 里的任务 = 立刻开始该任务**。不点击就什么都不会发生（P1 哲学的技术落地） |
| FR-D6 | 拖拽落位后可继续拖动调整时间；支持从 TL 移除条目（不删除任务本体） |
| FR-D7 | 支持：重命名 / 删除 TL、批量管理、一键导出码、导入 |

### E. 执行引擎

| 编号 | 规格 |
|---|---|
| FR-E1 | **全局同一时刻只允许一个任务处于 running 态**。这是硬约束，不做多任务并行 |
| FR-E2 | 开始前强制弹出 prospect 输入（一句话预期即可，可为空但需显式确认"跳过") |
| FR-E3 | 任务运行时可从三处操作：全局快捷键唤起的主界面 / 托盘菜单 / 浮窗（若开启） |
| FR-E4 | 暂停 / 继续 / 中止 / 完成 四个动作在以上三处都可用 |
| FR-E5 | 计时基于**绝对时间戳**计算，不依赖前端定时器累加。电脑睡眠、隐藏窗口、进程挂起后恢复，时长依然准确 |
| FR-E6 | 倒计时归零时按提示力度提醒，然后自动进入**结束流程**（不静默停止） |
| FR-E7 | ⚠️ `scheduled` 任务触发时若已有任务在跑 → 弹窗询问「是否打断当前任务」。选**否** → 该日程任务顺延，在当前任务结束后的空闲时刻再提醒一次 |
| FR-E8 | ⚠️ `scheduled` 任务触发时若电脑关机/软件未运行 → 下次启动时弹出补办提醒：「有一个日程任务未完成」 |
| FR-E9 | 正计时任务无自动结束，只能手动完成/中止 |

### F. 结束流程（这是产品的灵魂，不要简化）

| 编号 | 规格 |
|---|---|
| FR-F1 | 任务结束后进入全屏专注的结束界面，先给**完成确认**（时长、等级变化、coin 收益） |
| FR-F2 | 再进入**三问反思**，逐问出现，不做成一次性三个输入框：<br>① 这次的结果和你一开始的预期差在哪里？<br>② 在哪个瞬间开始，事情可以做得更好？<br>③ 下次你具体改做什么？ |
| FR-F3 | 三问答案写入 `task_runs.outcome` / `reflection`，并在该任务详情里可回看历史 |
| FR-F4 | 最后提示站起来休息几分钟，提供「休息 5 分钟」按钮（创建一个临时 countdown 任务） |
| FR-F5 | 中止（放弃）不进入反思三问，只记一次 `aborted`，不计 coin |

### G. 成就系统

| 编号 | 规格 |
|---|---|
| FR-G1 | **评级称号**：按累计专注时长/连续天数给称号（如 Lv.1 初学者 → 后期称号），随等级解锁 |
| FR-G2 | **热力图**：周视图 + 月视图，格子深浅 = 当日专注时长 |
| FR-G3 | **统计图表**：柱形图（每日/每周时长）+ 环形图（各任务时长占比），可直接看出时间花在哪 |
| FR-G4 | **等级规则**：任务累计专注每满 100 分钟升 1 级；完成任务本身给 coin，coin 数额与专注时长挂钩 |
| FR-G5 | **徽章**：每个徽章有触发条件（首次完成任务、连续 7 天全勤、累计专注 100 小时……），达成即弹徽章动画 |
| FR-G6 | 徽章可**一次性兑换**小额 coin，兑换后徽章保留但标记为已兑换 |
| FR-G7 | **装饰墙**：可摆放已购装饰品、已获得徽章、高等级任务卡片。可拖拽定位，位置持久化 |
| FR-G8 | **商店**：用 coin 购买装饰品（不做付费，纯游戏化） |

### H. 复盘系统

| 编号 | 规格 |
|---|---|
| FR-H1 | 复盘周期可配置：每天 / 每周 / 每月，各自独立开关与时间点 |
| FR-H2 | 到了复盘时间，主页面「任务复盘」入口显示**红点**（不是弹窗打扰） |
| FR-H3 | 复盘流程：系统给出提问提纲 + 自动填入本期数据（总时长、Top 任务、完成率、中断次数），用户在其后补充 |
| FR-H4 | 用户填完归档为 Markdown 文件，写入用户指定目录（默认 `~/Documents/Auxilia/reviews/`） |
| FR-H5 | 归档后在库中保留索引，可在软件内查看历史复盘 |
| FR-H6 | 累计写满 N 篇复盘给徽章 |

### I. 数据导入导出

| 编号 | 规格 |
|---|---|
| FR-I1 | 任务池、TaskLine 均支持「一键生成导出码」 |
| FR-I2 | 导出码 = `aux1:` + base64url(deflate(JSON))。**必须压缩**，否则长文本会超出可复制长度 |
| FR-I3 | 导入时校验前缀与版本号，失败给出明确原因，不静默失败 |
| FR-I4 | 批量管理支持：多选、批量删除、批量加入 TL、批量改属性 |

### J. 系统集成与性能

| 编号 | 规格 |
|---|---|
| FR-J1 | **开机自启**：默认开启，设置项可关，Windows 下写入启动项 |
| FR-J2 | **全局快捷键** `Shift+Space`：唤起/收起主窗口；唤起时窗口居中并聚焦到搜索框 |
| FR-J3 | **托盘常驻**：关闭主窗口 = 隐藏而非退出；托盘菜单含「显示」「暂停/继续」「结束当前任务」「退出」 |
| FR-J4 | **顶栏显示**：⚠️ Windows 无 macOS 菜单栏，落地为**贴屏幕顶部的置顶迷你浮条**（见 5.1） |
| FR-J5 | **浮窗**：always-on-top 小窗，可拖动，显示任务名 + 剩余时间 + 暂停/结束按钮 |
| FR-J6 | **性能预算**：空闲常驻内存 ≤ 120MB，前台 ≤ 250MB；冷启动到可交互 ≤ 1.5s；CPU 空闲占用 ≈ 0% |
| FR-J7 | 数据本地化：SQLite 单文件存于 `%APPDATA%/Auxilia/auxilia.db`，不联网 |

## 5. 歧义澄清与决策 ⚠️

这一章是我在理解需求时发现的模糊点和平台现实问题，给出**建议决策**。你确认或推翻后，这些决策会成为提示词里的硬约束。

### 5.1 ⚠️ "顶栏显示" 在 Windows 上不存在

macOS 有菜单栏（Menu Bar），可以在右上角常显。**Windows 没有等价物。** 三个可选落地：

| 方案 | 效果 | 评价 |
|---|---|---|
| A. 托盘图标 tooltip 动态更新 | 鼠标悬停托盘才看到 | 太隐蔽，不满足"常显" |
| **B. 置顶迷你浮条**（推荐） | 80×26 无边框窗口贴在屏幕顶部居中，显示 `● 25:00 写方案` | 视觉上就是"顶栏"，可拖动可隐藏 |
| C. 主窗口缩成胶囊贴顶 | 需要频繁切换窗口形态 | 状态复杂，易出 bug |

**建议：方案 B。** 用独立 Tauri 窗口，`always_on_top + decorations(false) + skip_taskbar(true)`。

### 5.2 ⚠️ "一次鼠标滚动为 1 分钟、1 小时"

这句话有两种读法，我按第一种落地：

- **读法一（采用）**：滚轮每格 = 1 分钟。左侧小时轮、右侧分钟轮，像 iOS 计时器。快速甩动可以一次跨多格。
- 读法二：需要两档灵敏度切换（慢滚 1 分钟、快滚 1 小时）——交互成本更高，且"手感"难统一。

**建议：读法一 + 快捷胶囊按钮兜底**（FR-C4）。用户要精确调 1 小时 30 分，用胶囊最快。

### 5.3 ⚠️ 是否允许同时运行多个任务

从「触发时已在执行任务则询问是否打断」推断，你设想的是**单任务串行**。

**建议：确认单任务串行（FR-E1）。** 这大幅简化了顶栏、浮窗、计时引擎的全部设计，也符合"专注"的产品定位。

### 5.4 ⚠️ 暂停的时间算不算专注时长

**建议：不算。** 计时引擎记录 `elapsed = Σ(每个 running 区间时长)`，暂停区间不计入 coin 和等级。

### 5.5 ⚠️ 中止 vs 完成 的 coin 差异

**建议：中止 = 0 coin，但保留时长记录用于统计；完成 = 按时长计 coin。** 否则"中止"会变成刷币手段。

### 5.6 ⚠️ 任务结束后的超时如何处理

倒计时归零即结束（FR-E6）。若用户离开电脑，结束后界面一直等着——这是对的，因为反思三问必须面对。

## 6. 边界条件清单（QA 会逐条打勾）

| # | 场景 | 期望行为 |
|---|---|---|
| E-1 | 计时中电脑休眠 2 小时 | 恢复后时长准确（时间戳差），倒计时可能已归零 → 立即进入结束流程 |
| E-2 | 计时中强制杀进程 | 重启后弹出「上次任务未正常结束」，可补记或丢弃 |
| E-3 | 倒计时最后 60 秒 | 状态色转为警示色 + 数字脉冲，不放大音量 |
| E-4 | 同一时间发起第二个任务 | 直接被拒绝并提示"正在执行 X"，不弹打断询问（打断只针对 scheduled） |
| E-5 | scheduled 任务触发时关机 | 启动后补办提醒（FR-E8） |
| E-6 | 快捷键与其他软件冲突 | 注册失败时明确提示并要求换键，不静默失效 |
| E-7 | 任务标题超长 | 单行省略，hover 显示全文 |
| E-8 | TaskLine 同一格放 10 个任务 | 纵向堆叠，格子自动撑高，不滚动嵌套 |
| E-9 | 导出码超长 | 超过 8000 字符时提示"内容过多，建议分批导出" |
| E-10 | 数据库写入失败 | 事务回滚 + 明确报错，不吞异常 |
| E-11 | 多显示器 / 分辨率变化 | 浮条与浮窗按主屏定位，显示器切换后重新计算 |
| E-12 | 系统缩放 125% / 150% | 所有尺寸用 CSS 逻辑像素，不出现模糊或错位 |

## 7. v1 范围边界

### 做
A ~ J 全章。其中 **E-7 / E-8 / 装饰墙拖拽** 可以放到 v1.1。

### 明确不做（v1）
- ❌ 手机端
- ❌ 云同步 / 账号体系
- ❌ 宣传视频
- ❌ 多人协作
- ❌ 番茄钟式的强制休息锁定
- ❌ 任何联网功能（除检查更新）

## 8. 验收的最终标准

v1 算完成，当且仅当：

1. 装好后开机自启，`Shift+Space` 能唤起。
2. 从零建一个 25 分钟倒计时任务，全程只用键盘 + 1 次鼠标点击，5 秒内开跑。
3. 跑的过程中关掉主窗口，托盘图标仍在走，顶栏浮条时间在减。
4. 归零后弹提醒 → 结束界面 → 三问 → 休息提示，链路不断。
5. 第二天打开，成就页有昨天的热力图格子，任务有等级和 coin。
6. 空闲放一整天，任务管理器里内存不超过 120MB。
